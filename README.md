# TNC RIDE SHARE 4 — สมัครทันที / เข้าด้วยเบอร์โทร / ไม่ส่งอีเมล

## สิ่งที่เปลี่ยน

- สมัครด้วยชื่อภาษาอังกฤษ เบอร์โทร 10 หลักขึ้นต้นด้วย 0 และอีเมล
- บันทึกสมาชิกลง public.tnc_profiles แล้วเข้าสู่ระบบทันที ไม่มี OTP ไม่มี SMTP และไม่มีคำขอไป Supabase Auth
- สมาชิกเดิมกรอกเบอร์โทรแล้วกดเข้าสู่ระบบ (หรือ Enter) เพื่อแสดงชื่อและใช้งาน ไม่ส่งคำขอทุกครั้งที่พิมพ์ตัวเลข
- ชื่อที่กรอกยอมรับ A-Z/a-z ช่องว่าง จุด ขีดกลาง และ apostrophe (เช่น John O'Neil) ต้องมีตัวอักษรอย่างน้อย 2 ตัว ความยาว 2–100
- อีเมลรับเฉพาะ ASCII ส่วนเบอร์รับตัวเลขเท่านั้น ตรวจซ้ำทั้งหน้าเว็บและเซิร์ฟเวอร์ การวางชื่อภาษาไทยจะไม่สามารถส่งฟอร์มได้
- ชื่อสถานที่จากแผนที่ขอเป็นภาษาอังกฤษ ถ้าผู้ให้บริการยังส่งภาษาอื่นมาจะใช้พิกัดแทน ป้ายหน้าจอและข้อความอธิบายภาษาไทยยังคงเดิม
- ประวัติ/สมาชิกที่มีอยู่เดิมไม่ถูกลบ ไม่แปลงชื่อเก่าหรือข้อมูลเดิมเป็นภาษาอังกฤษอัตโนมัติ
- ใครทราบเบอร์โทรก็เข้าเป็นสมาชิกนั้นได้ตามรูปแบบที่ร้องขอ ไม่ได้ยืนยันตัวตนหรือความเป็นเจ้าของอีเมล เหมาะกับขอบเขตการเข้าถึงที่คุณยอมรับได้เท่านั้น

## 1. อัปเกรดฐานข้อมูล Supabase เดิม

สำหรับโปรเจกต์ที่รัน SQL รุ่น Supabase ก่อนหน้านี้และมี tnc_profiles / tnc_trips / tnc_passengers แล้ว:

1. สำรองฐานข้อมูลก่อน
2. Supabase → SQL Editor → New query
3. วางเนื้อหา `supabase/upgrade-phone-login.sql` ทั้งไฟล์ แล้ว Run
4. ห้ามรัน new-project.sql ทับตารางเดิม ไฟล์อัปเกรดคง id สมาชิก เที่ยวรถและผู้โดยสารไว้

หากเป็น Supabase Project ใหม่ที่ยังไม่มีตาราง ให้รัน `supabase/new-project.sql` เพียงไฟล์เดียวแทน

รุ่นนี้ปล่อย auth_id ว่างได้สำหรับสมาชิกใหม่ ไม่สร้างแถวใน Authentication → Users สมาชิกใหม่ดูที่ Table Editor → tnc_profiles สมาชิกเก่าที่มีแต่ใน Auth Users แต่ไม่มี tnc_profiles ยังต้องสมัครในเว็บใหม่

ฟังก์ชันเดิมถูกปิดสิทธิ์ anon/authenticated และเปิดเฉพาะ RPC tnc_phone ให้ service_role ใช้ผ่าน Vercel ผู้ใช้หน้าเว็บไม่สามารถเลือก member ID เองได้

## 2. ตั้งค่า Vercel (ชื่อค่าต่างจากรุ่น OTP)

Vercel → Project → Settings → Environment Variables เพิ่ม Production และ Preview:

| Key | ค่า |
|---|---|
| SUPABASE_URL | Project URL เช่น https://xxxx.supabase.co |
| SUPABASE_SERVICE_ROLE_KEY | Secret key `sb_secret_...` หรือ legacy `service_role` จาก Supabase API Keys |
| SESSION_SECRET | ข้อความสุ่มลับอย่างน้อย 32 ตัวอักษร สำหรับลงลายเซ็น session |

**รุ่นนี้ต้องใช้กุญแจเซิร์ฟเวอร์ ไม่ใช่ publishable/anon key** ใส่เฉพาะ Vercel Environment Variables ห้ามใส่ HTML, GitHub, NEXT_PUBLIC_ หรือส่งในแชต ตัวอย่างใน .env.example ไม่ใช่ค่าจริง

SUPABASE_PUBLISHABLE_KEY และค่าของ Apps Script ไม่ได้ใช้แล้ว ไม่ต้องตั้ง SMTP หรือแก้ Email Templates เพื่อใช้งานรุ่นนี้

Cookie อายุ 24 ชั่วโมง ตรวจลายเซ็นฝั่งเซิร์ฟเวอร์ และตรวจสมาชิกยังมีอยู่ในฐานข้อมูลทุกครั้งที่เรียกข้อมูล ออกจากระบบล้าง cookie เปลี่ยน SESSION_SECRET จะทำให้ session เดิมทั้งหมดใช้ไม่ได้

## 3. แทนที่โค้ดใน VS Code

1. สำรองโปรเจกต์เดิม แล้วคัดลอกเนื้อหาโฟลเดอร์ชุดนี้ไปแทนที่ใน C:\Users\HP\Documents\GitHub\tnc_ride
2. ต้องแทนที่ทั้ง api/app.js และ public/index.html พร้อม package.json/vercel.json
3. ถ้ายังมี api/sheets.js ให้ลบออก และใช้เฉพาะ test/app.test.js รุ่นนี้แทน tests OTP เก่า
4. Commit / Push แล้ว Redeploy Vercel: Other, npm run build, Output Directory dist, Node.js 24.x
5. ไม่ต้องปิด email provider ของ Supabase ทั้งโปรเจกต์ โค้ดใหม่ไม่เรียกใช้ระบบนั้นอยู่แล้ว

## 4. ทดสอบ

1. สมัครชื่อ `Test Member` พร้อมเบอร์และอีเมลของคุณ → เข้าระบบทันที แสดงชื่อสมาชิก
2. Supabase Table Editor → tnc_profiles ตรวจแถวใหม่: name, phone, email, created_at โดย auth_id ว่างได้
3. ออกจากระบบแล้วกรอกเบอร์เดิม → ต้องแสดงชื่อเดิม
4. สมัครเบอร์เดิมซ้ำ → ต้องแจ้งให้เข้าสู่ระบบ ไม่เพิ่มแถว
5. กรอก/วางชื่อภาษาไทย → ต้องไม่รับสมัคร
6. สมาชิกที่มี tnc_profiles อยู่แล้วเข้าด้วยเบอร์เดิมและดูประวัติเดิมได้
7. ทดลองประกาศเที่ยวรถและร่วมรถด้วยอีกบัญชี เจ้าของเที่ยวรถเท่านั้นที่อัปเดตสถานะได้

ตรวจด้วย `node --test` และ `node scripts/build.js` แล้ว: syntax, การสมัคร/ล็อกอินด้วยเบอร์, input ภาษาอังกฤษ, session ปลอม, เบอร์ซ้ำและเครือข่ายขัดข้อง โดยใช้ฐานข้อมูลจำลอง ยังไม่ได้รัน SQL กับ Supabase จริงหรือ Deploy ในบัญชีของคุณ
